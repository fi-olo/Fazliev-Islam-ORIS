# Многопоточный сервер задач

Клиент-серверное приложение на TCP-сокетах для работы с общим списком задач.
Несколько клиентов одновременно работают с одним и тем же списком задач на сервере.

## Файлы проекта

- `server.py` — TCP-сервер, обслуживает несколько клиентов одновременно.
- `client.py` — клиент с консольным интерфейсом.
- `protocol.py` — общий модуль протокола (заголовок `command + length`).

## Как запустить

1. Запустить сервер:
   ```
   python server.py
   ```
   Сервер начнёт слушать `0.0.0.0:5555`.

2. В отдельных терминалах запустить одного или нескольких клиентов:
   ```
   python client.py
   ```
   Клиент подключится к `127.0.0.1:5555`.

## Команды программы

| Команда           | Действие                                    |
|-------------------|---------------------------------------------|
| `/add <text>`     | добавить новую задачу                       |
| `/list`           | показать все задачи                         |
| `/done <number>`  | отметить задачу с номером как выполненную   |
| `/delete <number>`| удалить задачу с номером                    |
| `/quit`           | завершить работу клиента                    |


## Как реализована одновременная работа нескольких клиентов

Сервер в main() после server.accept() создаёт отдельный поток
threading.Thread(target=handle_client, ...) на каждого подключившегося клиента.
Потоки работают независимо, поэтому сервер обслуживает несколько клиентов
параллельно. Каждый клиент при этом видит общий список задач, потому что
он хранится на сервере в переменной tasks.

## Где и зачем используется синхронизация

Общий список задач tasks изменяется из потоков разных клиентов.
Чтобы избежать состояния гонки (race condition), все операции чтения и
изменения списка выполняются внутри with tasks_lock: — это threading.Lock.

- tasks_lock защищает список tasks (команды /add, /list, /done, /delete).
- clients_lock защищает словарь clients (список активных подключений),

Благодаря блокировкам в один момент времени список изменяет только один поток,
поэтому данные не повреждаются, а клиенты всегда видят согласованный список.
